# 清潔箱配置決策支援 MVP

範圍：本文件說明原始 MVP／目前的**模式 A**，不是整個政策頁的最新功能清單。模式 B 已另加入類別平衡政策優先研究，詳見 [v1.2 方法](bin-policy-v1.2-methodology.zh-Hant.md)。以下來源稽核與結果保留原日期，不表示即時現況。

這個模組回應[「找回消失的垃圾桶」政策題目](https://puma.taipei/hackathon#issues)，協助分析人員找出「指定直線範圍內沒有已列冊清潔箱的公車站位」，並在箱數與假設預算下挑選優先現勘的參考點。

入口：`#/bin-policy`。這是決策支援原型，現勘點位須經權管與現場確認後才可考慮設置。

## 一次可以完成的決策流程

1. 看資料狀態：有效座標、重複座標、排除原因與來源日期。
2. 選行政區與直線半徑（200、300、500 公尺），輸入最多 50 個新增箱數。
3. 如需預算約束，填入每箱假設成本與可用假設預算，再按「套用情境」。
4. 比較 A 既有來源紀錄、B 新增情境、C 另一個半徑下的結果。C 會重算自己的基線，不能把半徑改變視為增設效益。
5. 打開候選證據，看來源 ID、最近箱距、新增覆蓋站位與重疊。點選地圖上的編號方塊可看同一候選資訊。
6. 匯出附方法識別、來源與日期的 JSON／CSV，或列印決策摘要。

## 為何選這些點

每個公車參考座標權重相同。先標記已有清潔箱於 R 內的站位，再從未覆蓋站位中選出「新增覆蓋數最多」的一點，更新覆蓋集合並重複。平手以穩定來源 ID 排序，每個新增覆蓋站位只計一次。數量達上限、預算不足、沒有新增覆蓋或無可用候選時停止。最小箱距只代表使用者輸入的假設。

方法為 `greedy-equal-reference-coverage-v1`，不保證全域最佳解。行政區篩選只限定參考點，距離分析保留跨區鄰近箱位，避免邊界偏差。地圖則優先顯示目標區資料。假設成本不包括維護、清運、工程或土地因素，也不是市府採購金額。

## 如何更新與驗證

```bash
npm ci
npm run data:convert:bin-policy -- data/raw/bin-policy/v1-14c24bcdbade
npm test
npm run build
npm run test:e2e -- --workers=2
npm run dev
```

v1.1 起，更新改為監測與發布分離。`npm run data:monitor:bin-policy -- test-results/bin-policy-monitor` 只檢查，不修改正式資料。`--accept-source-revision` 已不能單獨授權新版本；必須先審查精確雜湊、資源身分、日期、欄位、座標、完整性及決策影響，再以 approval JSON 準備隔離審查包及草稿 PR。程式不會自動合併或發布到主分支。原版本仍可由版本化原檔重建，來源失敗保留既有快照。完整流程見[資料治理指南](bin-policy-data-governance.zh-Hant.md)。

## v1.1 新增證據

- 「資料健康狀態」分開列出來源更新、擷取、驗證、發布及監測時間；未知不冒充即時。
- 「清潔箱資料對帳」保留 1,197 舊紀錄、681 原始列／679 去重位置、另份 130 列地點及 806 組／1,612 座公告的不同單位。對不上不代表撤除，附檔備註還包含多個「處」。見[對帳與主管機關待確認問題](bin-policy-bin-reconciliation.zh-Hant.md)。
- 「公車來源版本與敏感度比較」展示較新官方站位快照的品質與同參數比較；2021 來源仍為預設，新版待獨立審查，不混用母體。見[公車來源遷移證據](bin-policy-bus-stop-migration.md)。
- 既有 A/B/C、候選理由及匯出不變。較大的稽核檔僅在展開時載入；底圖失效不會阻擋清單與匯出。曾在正式預覽成功快取的分析可離線回復，畫面會明示無法確認目前來源狀態；未提供離線底圖下載。

政策 JSON 僅在開啟政策頁時載入，不由一般設施地圖預先載入；PWA 對政策資料採網路優先，離線可回退至曾載入的快取。來源日期與歷史資料提醒始終可見。原始檔與既有共用地圖資料分離。

## 現勘前還缺什麼

- 核對站位與清潔箱是否仍在、是否可用。
- 確認人行淨寬、通行障礙、土地與設施權管。
- 與居民及商家確認可能影響，再由主管機關確認清運動線、維護能力及實際成本。

本次沒有使用捷運旅運量作權重（官方資源為每月 URL 索引，尚未完成 OD 與站位整合）、沒有陳情座標（公開欄位缺少可靠地理資訊）、沒有 IoT 滿溢感測。後續可加入更新站位、步行網路、經查證的權重與政府審查流程，但須另外建立證據，不能由目前站位數推論行人流量、垃圾需求、環境公平、非法棄置或政策效益。

完整方法、來源日期、資料品質、架構、測試與更新程序見 [methodology](bin-policy-methodology.md)。
