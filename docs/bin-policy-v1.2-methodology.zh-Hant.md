# 政策優先配置：方法、解讀與操作

## 模式與操作流程

既有 `#/bin-policy` 新增明確模式切換。模式 A 保留原本 `greedy-equal-reference-coverage-v1`、679 個箱位與 3,395 個 2021 公車參考點，原 A/B/C 半徑／預算與匯出意義不變。模式 B 為 `policy-balanced-coverage-v1`，只在選取後載入待審研究資料。兩者的分數單位不同，不直接比較高低。

流程：選模式 → 看假設及缺漏 → 調整權重、行政區、半徑、箱數與成本／預算 → 執行情境 → 查看候選點各類貢獻 → 比較敏感度 → 匯出摘要。修改條件後，舊結果會明示仍為上次情境，不會每按一鍵就重跑昂貴空間計算。

## 權重不是官方係數

[2026-08-10 官方政策背景](https://www.gov.taipei/News_Content.aspx?n=F0DDAF49B89E9413&s=798A998A29BE46CD) 支持關注商圈、夜市／攤販、觀光及公共活動，但沒有提供數值公式。`policy-priority-weights-v1` 採本研究明示的假設：

| 類別 | 預設權重 | 本次全市有效母體 |
| --- | ---: | ---: |
| 觀光景點 | 4 | 缺漏：官方 API HTTP403 |
| 夜市／官方攤販集中場 | 4 | 42 處官方集中場；不能宣稱全部是夜市 |
| 傳統市場 | 3 | 47 |
| 具空間證據商圈 | 3 | 缺漏：235 筆通訊／介紹僅作背景 |
| 捷運站參考位置 | 2 | 73 個站體參考位置，非出入口 |
| 原核准公車參考位置 | 1 | 3,395 |

權重 4 不代表四倍垃圾量或人流。可編輯六個完整、有限且介於 0–10 的值；空白、負值、NaN、無限大及超界值不會自動修正。重設按鈕讀取中央版本化設定。預設或語意改變須遞增設定版本；自訂情境保存實際值。

## 為何不直接把所有點的權重相加

直接加總仍會被數千筆公車資料支配。因此每類 k 以選定範圍內有效、去重的實體數 N_k 正規化：

`本步新增分數 = Σ（w_k × 此候選點本步新增覆蓋數_k ÷ N_k）`

N 包含既有箱已覆蓋的實體，在同一情境全部選點過程與權重比較中固定。N=0 就不納入該項，明示無可用母體，不把缺漏權重挪給交通類。權重 0 只代表本次不給優先分數，不是零需求。N<5 提醒樣本稀少，並非統計信賴度。

全域先處理有證據的 canonical identity，再篩行政區。跨類別確定別名採觀光→攤販→市場→商圈→捷運→公車的固定主類別；不因地點靠近而合併。不同實體即使同座標也可保持獨立母體；完全相同候選錨點座標則以穩定 ID 留一點，不等於把參考實體合併。原始值、別名與排除證據均保留，詳見[來源稽核](bin-policy-v1.2-sources.md)。

## 候選點與計算限制

- 先驗證來源版本、類別可用狀態、座標、實體及雜湊；背景商圈通訊地址、受阻 API 不可偷渡成計分點。
- 區界檔必須與原核准快照的 SHA256 一致；其來源亦列入匯出。原檔封存檢查不冒充空間驗證；研究快照另外記錄實際完成空間／契約驗證時間。
- 覆蓋採含邊界的 Haversine 直線距離；跨區附近既有箱也可提供覆蓋。網格只加速候選查詢，最後仍做精確距離篩選。
- 預設候選錨點來自公車與捷運，可切為僅公車。景點、市場是參考母體，並未直接變成建議設箱位置。已被既有箱覆蓋的交通錨點仍可能覆蓋其他類的缺口。
- 預計算尚未覆蓋鄰居集合，逐步挑最大正增益並移除已覆蓋 ID，避免重複計數。等分以穩定 ID 排序；分數相對容忍為 `1e-12 × max(|score|, |bestScore|)`，不因全部合法權重等比縮小就把正增益當成零或改變排序。距離容忍為 1e-7 公尺，不表示原始座標精度。
- 箱數 0–50；成本與預算皆提供時採 `floor(預算／每箱成本)`。零預算可選零點；不含維運、清運或工程。最小距離只針對既有箱，不偷加候選之間的距離限制。
- [歷史程序已於 2022-08-24 停止適用](https://laws.gov.taipei/Law/LawSearch/LawArticleContent/FL076512)，其中寬度及 50m 不作現行法律規則。距離是分析假設；現行規範、土地權管、人行淨寬、障礙物、住商影響與清運能力仍須現勘確認。

## 敏感度如何閱讀

相同母體、來源、半徑、候選池、成本／預算與距離下，比較：類別等優先（各可用類為 1）、文件預設 4/4/3/3/2/1、目前自訂權重，以及各可用類別從**文件預設**單獨 ±25%，其他類不變。超出合法設定範圍的變動會明示跳過，不默默截斷。

每個候選點會列出新增原始實體數、各類新增數／N、權重乘積、總分、最近既有箱、來源精度與敏感度入選次數；完整表可看各情境名次及未入選。破折號是未入選，不是名次不變；不另外宣稱「穩健」。

本次凍結資料的全市 300m／10 點範例，等優先與政策預設都新增覆蓋 125 個原始實體，但 `bus-1210` 從第 7 移至第 3。這顯示優先取捨，不代表垃圾減量或成本改善；不同權重本來就會改變分數尺度，不能把較高分數當施政成效。

## 匯出、治理與可重現性

來源版本、方法版本、權重版本各自獨立。研究快照維持 `review_required`；技術審查不是政府設置核准。原核准箱位與公車版本未變，監測只報告，不自動取代。

JSON 保存精確權重、類別定義、來源 ID／雜湊／日期、基線與公車版本、來源原檔檢查及實際分析驗證／產生時間、全部敏感度與排除限制。CSV 包含情境摘要（零候選仍有）、類別摘要與候選列，分開原始覆蓋與加權分數，並防止來源字串被試算表當公式執行。原模式匯出不變。

執行指令、測試、效能與限制見[v1.2 實作紀錄](bin-policy-v1.2-audit.md)及[研究資料治理](bin-policy-v1.2-governance.md)。本次不做政府簽核、清運派車、滿溢感測、家戶棄置預測或跨專案整合。

可用 `npm run data:example:policy-priority` 重建已保存的[範例 JSON](../reports/bin-policy-v1.2/example-analysis.json)及[CSV](../reports/bin-policy-v1.2/example-analysis.csv)。[桌面](images/bin-policy-v1.2-controls-desktop.png)與[手機](images/bin-policy-v1.2-controls-mobile.png)截圖為本機研究介面，不冒稱公開正式部署。
