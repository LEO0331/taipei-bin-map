# 臺北公共設施與涼適點資訊：決策應用與營運建議

## 文件目的與閱讀方式

本文件說明此平台可如何支援實際服務決策，也同時界定資料不可支持的結論。它適合供公共服務團隊、社區組織、研究與產品負責人用來討論「下一步該查什麼、補什麼資料、改善哪個服務環節」，不應直接取代現場巡查、服務營運系統或主管機關的正式判定。

平台目前採靜態公開資料架構。主公共設施資料的既有轉換報告包含 16,956 筆有效紀錄；另有獨立的公立學校校園開放資料（224 所學校）與臺北市涼適點資料（494 處、其中 491 處具有效官方座標）。不同模組的更新日期、來源完整度和定位精度不相同，因此跨模組比較時，應先確認其資料日期與欄位定義。

## 這個平台最有價值的三種用途

### 1. 協助民眾建立「可確認的候選清單」

平台最適合回答的是「我現在或接下來要去哪裡查找服務」：

- 依位置、行政區和設施類型尋找公廁、飲水設施、回收據點、停車或充電服務。
- 在高溫情境中，以室內／戶外、冷氣、飲水、廁所、座位與無障礙座位查找涼適點候選位置。
- 依學校、行政區、日別及時段建立校園開放場地的詢問清單。
- 將地址、電話與來源開放時間帶到下一步：致電、查看官方公告或到現場確認。

設計上的關鍵是「縮小不確定性」，不是宣稱即時可用。這對市民而言很實用：在資訊分散時，先找到少量相對符合需求的候選點，再用官方或現場資訊確認，通常比自行搜尋多個網站更有效率。

### 2. 支援服務覆蓋與資料缺口的初步盤點

行政區、設施類型、座標有效性與欄位覆蓋率，可支援以下問題：

- 哪些行政區在特定來源中有較少紀錄？這是實際服務缺口，還是尚未納入資料？
- 某類設施有多少筆具有效座標，能支援附近搜尋；有多少只能作為地址型目錄？
- 涼適點中，來源列示冷氣、飲水、廁所與座位的交集有多少？哪些行政區的「來源記錄覆蓋」較完整？
- 哪些資料集的電話、地址、座標、開放時間或無障礙欄位需要優先補齊？

這些結果應命名為「資料覆蓋」或「來源列示情形」，而非服務品質、熱風險或行政區排名。資料筆數可能受資料提供方式、資料更新週期與登錄範圍影響，不能單獨作為預算、績效或安全評分依據。

### 3. 建立與資料提供單位的改善清單

每個轉換器保留原始文字並產出品質資訊，例如缺失欄位、重複列、異常座標、未知值與格式異常。這使資料治理可以從抽象討論轉成可執行事項：

| 優先問題 | 對使用者的影響 | 建議與資料提供單位確認 |
| --- | --- | --- |
| 無官方座標 | 不能可靠計算距離或繪製精確地圖 | 補提供 WGS84 座標與位置精度欄位 |
| 開放時間是自由文字 | 不能可靠提供「目前營業」狀態 | 增加結構化日別、起訖時間與例外日欄位 |
| 設施值為空白或描述文字 | 無法確定設備是否存在或可用 | 區分有、無、條件式、未知及最後核實日期 |
| 同名／同址或重複紀錄 | 容易誤以為服務據點更多 | 提供穩定的官方識別碼與異動狀態 |
| 地址與行政區不一致 | 容易導向錯誤的區域統計 | 由權責單位確認地址、行政區與坐標的權威來源 |

## 涼適點模組：可採取的實務行動

涼適點是此平台最適合用於高溫日服務溝通的模組。資料目前列出 494 處，涵蓋 12 個行政區；491 處具有效官方座標。來源列示的設備數量為：冷氣 202、電風扇 147、廁所 319、座位 410、飲水設施 271、無障礙座位 66。

建議的使用方式如下：

1. **民眾服務頁或客服引導**：先選擇所需條件（例如冷氣、飲水、廁所、座位），再使用定位後的 500m、1km、2km 或 5km 範圍。結果的「符合 X 項需求」僅是來源列示設備的匹配數，不是場所好壞或安全程度。
2. **高溫期間的溝通素材**：以「附近可進一步確認的休息選項」呈現，並保留開放時間、電話與「請確認」提示；不要稱為緊急避難所，除非另有正式指定資料。
3. **無障礙服務改善**：把來源列示無障礙座位的 66 筆當作候選清單，安排後續查核入口、動線、電梯與無障礙廁所；切勿由座位欄位推論完整無障礙性。
4. **跨服務導流**：涼適點附近的飲水或廁所可提供「查看其他附近公共設施」入口，但必須維持資料來源分離，只有在有共同官方識別碼時才可合併為同一地點。

目前涼適點資料品質已識別出 2 筆缺少座標、1 筆超出合理範圍、2 筆電話格式異常，以及少數設備值屬條件式／空白。這些紀錄仍應保留在目錄與品質頁面，不應因為無法上圖而被刪除；同時應列為回報或人工查核優先項目。

## 校園開放資料：要避免的錯誤決策

224 所學校的資料可用來協助查找校園開放時段，但來源沒有提供完整的場地類型、預約連結、價格、電話、地址或權威座標。系統因此採取保守規則：

- 校園開放不等於場地可預約，也不代表特定運動設施存在或有空檔。
- 只有在來源文字明確提及運動名稱時才標示關鍵字；不會由羽球、網球或多功能場地推論匹克球。
- 解析後時段是方便檢索的衍生資訊，原始文字仍是主要依據。

對教育局或校方而言，最有價值的下一步是補上機關代碼可對應的官方地址、聯絡窗口、可預約場地、預約規則與更新日期，並將臨時關閉、考試、維修與假日例外納入結構化資料。

## 架構與資料量：目前的取捨是否合理

### 靜態資料與離線快取

平台將公開資料先在建置階段轉成 JSON，再由前端載入；PWA service worker 會快取應用程式外殼與資料。這對「非即時、可公開、以查找為主」的服務有明確優點：無需帳號、後端、資料庫或付費地圖 API，可部署到靜態託管環境，也能提升重複造訪與網路不穩時的使用體驗。

代價是資料可能落後於來源。實務上應建立資料新鮮度政策：每個模組顯示來源更新日、匯入日與下次檢查日；超過門檻時顯示「資料可能過期」；更新時保留前後版本差異。現有主轉換報告與新增獨立模組的資料日期並不完全同步，這正是應優先補強的治理項目。

### 大量資料下的地圖與清單設計

主設施資料接近 17,000 筆，直接繪製每一個 Leaflet marker 會使行動裝置的縮放、拖曳和點擊顯著變慢。現行策略是：

- 廣域、多圖層結果採清單優先，不一次繪製所有點。
- 使用者縮小到單一類型、行政區、關鍵字或附近結果，且有效座標不超過 500 筆時，再顯示精確 marker。
- 初始清單限制為 80 筆，避免過長卡片造成渲染與認知負擔。
- 涼適點在大範圍結果採網格叢集，縮小篩選後顯示個別點位。
- 地圖與涼適點模組採延遲載入，降低首頁初始載入量。

這個做法的取捨是廣域地圖不會「看見所有點」，但換取了可操作性和較清楚的搜尋任務。若未來需要用地圖做密度探索或跨區域規劃，可評估 marker clustering 套件、Canvas/WebGL 圖層、向量圖磚，或後端地理空間查詢。後兩者適合資料規模持續成長、需要即時更新或複雜篩選時，但會增加維運、成本與資安責任。

## 位置、隱私與可近性原則

附近搜尋只在使用者明確授權後於本次瀏覽器工作階段計算距離；位置不應傳送到伺服器或寫入長期儲存。拒絕定位後仍必須可用行政區、地址和名稱搜尋，這也是低數位能力或隱私敏感使用者的重要替代路徑。

地址型資料不應被自動地理編碼成精確標記。錯誤的精確位置比沒有地圖點更具誤導性。對座標失效、來源缺座標或僅有模糊位置描述的紀錄，應保留其目錄可見性、標示精度，並提供可用的地址複製或外部地圖查詢。

無障礙欄位也應以來源語意為限：有「無障礙座位」並不能推論無障礙入口、電梯、廁所或無障礙動線。這項原則可避免服務承諾超過證據範圍。

## 建議的營運指標與節奏

若要把平台從查詢工具提升為可持續的服務，建議每月或每季追蹤以下指標：

| 面向 | 建議指標 | 可支持的行動 |
| --- | --- | --- |
| 資料新鮮度 | 各模組距上次匯入與來源更新的天數 | 排定重抓、更新或標示過期 |
| 定位可用性 | 有效座標率、地址型紀錄率、座標異常率 | 優先要求高使用模組補座標 |
| 欄位完整度 | 電話、開放時間、設備、無障礙資訊的填寫率 | 與權責單位確認最值得補齊的欄位 |
| 使用任務 | 篩選組合、附近搜尋啟用率、無結果率 | 調整快速篩選與資料蒐集方向 |
| 資料異動 | 新增、刪除、地址／座標／設備變更數 | 追蹤資料品質與公告機制 |
| 人工確認 | 回報或查核完成率、修正時間 | 建立跨單位責任與服務水準 |

平台目前未蒐集這些使用行為，這符合低隱私風險的靜態產品定位。若未來要加入匿名使用分析，應先明確告知用途、採最小化資料、避免儲存精確位置，並提供不追蹤的替代使用方式。

## 分階段改善建議

### 近期：提高可信度與可理解性

1. 統一在每個模組顯示來源名稱、來源更新日、匯入日、欄位限制與資料品質摘要。
2. 修復並持續檢查所有對外繁體中文文件的 UTF-8 編碼，將此納入 CI 或文件檢核。
3. 在「沒有結果」時，顯示可調整的條件與原因（例如資料未提供座標、無明確設備值），而非只顯示空白。
4. 對高風險語意建立共用提示：即時狀態、可預約、醫療／緊急服務與完整無障礙性均需另行確認。

### 中期：提升資料治理與服務深度

1. 建立資料更新排程與差異報告，讓資料提供單位能看到新增、刪除、欄位變動與異常列。
2. 對涼適點與學校模組建立官方識別碼對應表；只用精確識別碼連結地址、座標、電話或預約資料。
3. 以匿名、最小化方式量測無結果率與常用篩選組合，優先補強民眾確實在找但資料不足的服務。
4. 為資料品質頁提供可下載或可回報的問題清單，縮短民眾回饋到資料修正的迴路。

### 長期：在證據足夠後再擴充決策能力

只有在取得即時、具責任歸屬且可追溯的來源後，才應新增「目前開放」、「即時空位」、「可預約」或即時設備狀態。若要進行服務可近性、熱風險或資源配置分析，還需要人口、步行路網、使用量、天氣、營運容量和服務邊界等額外資料，並應由領域專家共同定義方法與公平性檢查。

## 結論

此平台的主要價值是把異質公開資料轉成可搜尋、可說明、且能誠實表達不確定性的服務入口。它應被用來協助民眾尋找下一個可確認的服務選項，也協助管理者看見資料覆蓋、品質和更新流程的缺口。最重要的原則是：資料所支持的就清楚呈現；資料未支持的，就明確標示需要確認。這比以不完整資料做出看似精準的承諾，更能建立長期信任。
