## 配對規則

1. 有經驗證、相同命名空間的官方穩定 ID 時優先使用；本次三份來源均未提供此種 ID。本地序號只用於稽核。
2. 地址正規化全半形、臺／台、空白及括號逗號，保留 `-`、`/`、`#` 等門牌符號；地址與來源行政區都相同、且雙向唯一才配對。
3. 同址同座標為 `confirmed_match`；座標有小幅差異為 `probable_match`；同址超過預設 50 公尺為 `possible_location_change`，仍不能確定搬遷。
4. 不同地址但精確同座標或預設 25 公尺內，只構成 `ambiguous` 人工檢核線索，不據此認定身分相同。競爭的一對多群組整體保留，不強迫分派。
5. 無支持對象的歷史／現行列分別為 `historical_only`／`current_only`，並非撤除／新增；身分資料不足為 `unresolved`；無效座標或明確錯誤識別為 `invalid_source_record`。
6. 已有不同官方 ID 者不以較弱地址規則覆蓋；重複官方 ID 先保留模糊群組。跨來源範圍不直接配對。

所有有效來源列只屬於一個輸出關係。結果依穩定的輸入列識別排序；不受輸入陣列順序影響。半徑是檢核線索容差，不是座標測量精度聲明。

|---|---:|---|

| probable_match | 42 | 唯一同址同區，位置小幅差異，仍需確認 |

除 confirmed／probable 以外有 725 個待釐清關係，且 probable 也不等於人工認證。13 個疑似位置變動距離約 56.7～1,572.7 公尺；不能僅因地址相同就證實同一箱體搬遷。不同分類涵蓋不同列數：分類表是**關係數**，來源表才是**來源列數**。

目前可以重現哪些列能對應，但尚不能完整解釋兩版清單及公告數量為何不同。需要主管機關回覆定義與逐筆異動紀錄。

## 重現與稽核

```powershell
# 首次且尚無原始補充資源才需要網路；變更內容不會靜默覆蓋
npx tsx scripts/reconcileBinSources.ts --fetch-supplement

# 後續只讀已保存原始資料，不需網路
npx tsx scripts/reconcileBinSources.ts

# 可配置近鄰線索／疑似移動門檻，產生不同內容版本
npx tsx scripts/reconcileBinSources.ts --near-meters 15 --location-change-meters 50

npx vitest run src/lib/binPolicyReconciliation.test.ts scripts/reconcileBinSources.test.ts
```

輸入：既有歷史 JSON、政策版本的原始主 CSV、`data/raw/bin-policy-reconciliation/tourist-commercial.csv` 與 source manifest。原始內容 SHA256 驗證失敗即停止，不修改政策資料；同一補充下載 URL 若內容改變，也會拒絕覆蓋，需另建經審閱的原始版本。

輸出：`public/data/bin-policy/reconciliation.json`（前端固定入口）、`reconcile-v1-<digest>.json`（內容版本）、`reconciliation.csv`（逐筆稽核）、`reconciliation-summary.md`（可讀摘要）。報告版本取來源 hash、方法、門檻及配對結果的雜湊，重跑同一版本保留首次報告產生時間。產生時間不是來源發布、資料擷取或正式發布時間。
